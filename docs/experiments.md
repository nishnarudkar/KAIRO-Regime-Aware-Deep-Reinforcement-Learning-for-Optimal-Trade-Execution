## 2. Market Scenarios

All data is explicitly **synthetic** — generated with deterministic seeds.

| Scenario | Description |
|---|---|
| `normal` | Moderate volatility, normal liquidity. Baseline conditions. |
| `high_volatility` | Elevated price swings, wider spreads. |
| `low_liquidity` | Thin market, low volume, high per-share impact. |
| `stress` | Extreme volatility, very wide spreads, mild downward drift. |
| `regime_transition` | First half calm, second half high-volatility. Tests adaptation. |
| `liquidity_shock` | Normal conditions then sudden 90% volume collapse at midpoint. |

## 3. Experimental Design

### Data Splits (chronological — never shuffled)

```
All data (200 bars per scenario):
  ├── Train  (0%–70%)   → HMM fit + DQN training
  └── Test   (70%–100%) → all strategy evaluation
```

**Hard rule:** HMM is fitted on the training split only.
Regime labels for test observations are generated by the HMM Forward Algorithm
using only observations `X_{1:t}` (zero lookahead).

### Seeds

Default: `[42, 123, 777]`

Each seed generates a different data realization and different DQN weight
initialization. Results are reported as mean ± std across seeds.

### DQN Hyperparameters (identical for Models A, B, C)

All hyperparameters documented in `config/dqn.yaml`. No silent changes.

---

## 4. Ablation Study (Model C)

**Purpose:** Determine whether any Model B improvement over Model A is due to:
- (a) Causally useful regime information, OR
- (b) Simply adding extra feature dimensions to the state

**Method:** Replace HMM regime output with randomly sampled noise:
- `regime_id` ∈ {0,1,2,3} drawn uniformly at random
- `regime_probs` drawn from Dirichlet(1,1,1,1) — uniform random simplex

The shuffled noise is generated from a fixed seed (`shuffle_seed = dqn_seed + 1000`)
that is NOT correlated with price data.

**Decision rule:**
- Model B >> Model C → regime information is genuinely useful
- Model B ≈ Model C → extra feature dimension explains the improvement

## 5. Metrics

| Metric | Unit | Definition |
|---|---|---|
| Implementation Shortfall (IS) | bps | `(avg_exec - arrival) / arrival × 10_000` |
| Execution Cost | $ | Total $ cost vs arrival price |
| Market Impact Cost | $ | Almgren-Chriss temporary + permanent impact |
| Completion Rate | % | `executed / target × 100` |
| VWAP Slippage | bps | `(avg_exec - market_vwap) / market_vwap × 10_000` |
| Terminal Penalty | $ | Penalty for unexecuted inventory at horizon |
| Reward Total | — | Cumulative RL reward (DRL models only) |

## 7. How to Run

```bash
# Quick smoke test (1 scenario, 1 seed, 5 000 steps)
python scripts/run_experiments.py --scenarios normal --seeds 42 --timesteps 5000

# Full research run (all scenarios, 3 seeds, 50 000 steps each)
python scripts/run_experiments.py --timesteps 50000
```

## 8. Hard Rule Compliance

- No shuffling of time-series data ✅
- HMM fitted on train split only ✅
- Regime labels causally generated (HMM forward filter) ✅
- Every run records: seed, scenario, strategy, config ✅
- Results are reported as observed — no filtering or selection ✅
- Model C control included to prevent false positive conclusions ✅
