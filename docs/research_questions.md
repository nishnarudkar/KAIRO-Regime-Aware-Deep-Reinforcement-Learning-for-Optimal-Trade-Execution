# Research Questions

This document defines the formal research questions for the KAIRO project
and specifies exactly what experiment answers each one.

---

## RQ1 — Does RL outperform conventional execution baselines?

**Hypothesis:** A DQN agent trained on the Trade Execution MDP will achieve
lower implementation shortfall (IS) than TWAP, VWAP, and POV strategies
under the same market conditions.

**Experiment (Stage 6 + Stage 7):**
- Model: Standard DQN (no regime information)
- Baselines: TWAP, VWAP, POV
- Condition: Same market data, same impact model, same action space, same reward
- Metric: Implementation Shortfall in basis points (IS bps), execution cost ($),
  completion rate (%), VWAP slippage (bps)

**Decision Rule:**
- If DQN IS bps < best baseline IS bps on the **test set** → evidence for RQ1
- If DQN completion rate < 95% → DRL agent has an inventory risk problem

**Important:** We report what the experiment shows — we do NOT assume RL wins.

---

## RQ2 — Does regime information improve RL execution quality?

**Hypothesis:** An RL agent whose state includes causally-inferred HMM market
regime information will achieve lower implementation shortfall than an otherwise
identical RL agent without regime information.

**Experiment (Stage 7):**
- Model A: Standard DQN — state = market features + order state (7 dims)
- Model B: Regime-Aware DQN — state = market features + order state + HMM regime (12 dims)
- All other conditions identical: same data split, same training timesteps,
  same seed, same hyperparameters, same reward, same simulator
- Metric: Implementation Shortfall (IS bps), execution cost, completion rate

**Decision Rule:**
- If Model B IS bps < Model A IS bps on the **test set** → evidence for RQ2
- Statistical comparison requires multiple seeds (see Stage 8)

**Leakage Control:**
The regime label S_t is generated by the HMM Forward Algorithm using only
observations X_{1:t}. Future data X_{t+1:T} has zero influence. HMM is fitted
on the training split only.

---

## RQ3 — Does regime awareness improve robustness during regime transitions?

**Hypothesis:** A Regime-Aware DQN agent will adapt its execution strategy
during market regime transitions, outperforming the non-regime DQN particularly
in High Volatility and Stress regimes.

**Experiment (Stage 8 — Ablation Study):**
- Breakdown execution quality metrics *per regime* for Model A and Model B
- Identify if the improvement from regime information is concentrated during
  specific regime types (e.g., stress periods)

**Control condition (critical):**
- Model C: RL with **shuffled/randomized** regime labels as an uninformative control
- If Model B ≈ Model C in performance → regime *labels* are not useful, the
  improvement (if any) comes from the extra feature dimension rather than
  genuine regime information

**Decision Rule:**
- If Model B > Model C AND Model B > Model A during stress/transition periods
  → strong evidence that regime information is causally useful

## Definitions

| Term | Definition |
|---|---|
| **Implementation Shortfall (IS)** | `(avg_execution_price - arrival_price) * executed_qty` |
| **IS in bps** | `IS / (arrival_price * executed_qty) * 10_000` |
| **Completion rate** | `executed_qty / target_qty` |
| **VWAP slippage** | `(avg_exec_price - market_vwap_price) / market_vwap_price * 10_000` |
| **Regime label** | Causally-inferred HMM hidden state ∈ {Low Vol, Normal, High Vol, Stress} |
| **Train split** | Chronologically first 70% of data |
| **Test split** | Chronologically last 30% of data |

---

## Hard Requirements (Hard Rules §3)

- No shuffling of time-series data
- No future regime labels in any state vector
- No fabricated results
- Every experiment run records: seed, config, dataset version, model version
- Results are reported as observed — not selectively filtered
